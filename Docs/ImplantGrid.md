# RimCBM 二维植入体系统

本文件替代整体方案中的标量容量与“安装即启用”模型。用户在 2026-09-10 确认二维槽位、手术后待安装、研究后板内重排及双向热插拔规则；以下补充规则为实现决策。

## 状态与权限

| 状态/动作 | 条件与结果 |
|---|---|
| 体外 CBM → 手术准备 | 消耗物品，绑定角色和实际身体区域，进入“待安装·手术已准备” |
| 首次拖入 | 检查形状、宿主、冲突；普通格也允许，消费首次安装资格 |
| 已部署 → 同板重排 | 研究“植入体布局重构”完成；允许移动与 90°旋转，不新增拆卸权限 |
| 已部署 → 待安装 | 始终禁止，热插拔与研究均不例外 |
| 已部署 → 体外实物 | 模块支持热插拔且所有占用格均为热插拔，才允许直接拔出 |
| 体外实物 → 部署 | 实际物品可用且模块与目标所有格均支持热插拔；直接进入格子，不经过待安装 |
| 普通模块取出 | 通过对应实例的拆卸手术回到体外物品；不能直接按按钮删除植入物 |
| 再次准备普通安装 | 拆出的体外物品若要插入普通格，需要新的手术准备 |

板内重排科技与热插拔是两种独立权限。双向热插拔满足时，不需要研究便可拔出再插入；科技完成也不能将任何模块拖回列表。研究开放同板一次原子移动，不开放“暂时拿到列表腾地方”。拖动幽灵不会改变占用，落点提交失败则原位不变。待安装状态只有“经手术准备”一种，不记录热插拔来源。

一个覆盖四格的 CBM 必须四格全部为热插拔才可拔出。格子是否热插拔由宿主/扩展板定义，不能靠覆盖一个所谓转接器把普通连接即时变热插拔。研究完成后，支持热插拔的模块可以重排到全热插拔区域再拔出，这是两项能力的合法组合。

待安装件不提供能力、能源容量或扩容；列表显示绑定部位和大小。它是体内已完成医疗准备的暂存状态，不可出售、丢地或跨角色转移。被截肢时随宿主失去，不能转成免费物品。取消这类医疗准备、取回物品仍需手术。热插拔针对实际库存物品：原型仅允许角色随身库存直接接入，拔出的物品返回随身库存；不能在仓库与角色之间瞬移物品。未来远处物品接入通过搬运/操作 Job 实现。

## 身体板与扩容

首轮示例：原生手臂/腿部 2×3，仿生臂/腿 3×6；躯干 3×4；头部、手部、足部 2×2。原版仿生臂/腿会把下属手/足标为由整体义肢替代，因此这些不存在的天然部位不再单独提供槽位。数值除用户举例外均是原型候选，均由 Def 定义。不能按左右肢体的翻译文本绑定：使用实际 BodyPartRecord 和存档引用。

每格拥有多个不互斥的 tag，例如 `BodyPart.Arm` 与 `HotSwap` 可同时存在；没有 `HotSwap` 表示固定连接。格子同时保存由哪个扩容器提供。矩形 CBM 可定义宽、高及能否旋转。第一版采用矩形，预留不规则形状的后续扩展，不同时引入重量、插槽点数等额外资源。

### 多 tag 与安装限制（2026-09-11）

tag 为区分大小写的稳定字符串 ID，以集合处理：同一 tag 不重复计数，不同 tag 不互斥。CBM 的 `hotSwappable` 仍表示模块本身的热插拔能力，格子侧以 `HotSwap` tag 表示。

宿主定义支持三层：`hostTags` 加到本部位的所有格子并传播到扩展行、列和独立板；`defaultCellTags` 仅加到主板原始格；`cellTags` 为指定坐标追加 tag。扩容器用 `grantedCellTags` 声明新增格的能力，不能自动继承原始格的热插拔能力。

CBM 的 `requiredAllTags` 要求每个占用格具备列表中的全部 tag；`requiredAnyTags` 非空时要求每格至少匹配其中一个；`forbiddenTags` 禁止任何占用格带有其中的 tag。三个条件同时满足才可部署，不是把所有占用格的 tag 合并后检查。空列表表示无该项限制。

普通首次部署、研究后的重排和热插入均使用同一校验，不能通过手术或研究绕过。部位限定的模块可以放进该部位的扩展板，因为扩展板继承部位身份；待安装列表仍只能由手术加入。失去安装资格的扩容器不会继续提供空间。

例如仿生臂的原始格配置可以同时拥有部位、热插拔和其他能力：

```xml
<hostTags><li>BodyPart.Arm</li></hostTags>
<cellTags>
  <li><x>2</x><y>0</y><tags><li>HotSwap</li><li>Medical</li></tags></li>
</cellTags>
```

对应 CBM 的 DefModExtension 可声明只允许手臂、且每格具备医疗或工具接口：

```xml
<requiredAllTags><li>BodyPart.Arm</li></requiredAllTags>
<requiredAnyTags><li>Medical</li><li>ToolSocket</li></requiredAnyTags>
<forbiddenTags><li>DamagedSocket</li></forbiddenTags>
```

现有身体配置已加入 `BodyPart.Torso`、`BodyPart.Head`、`BodyPart.Arm`、`BodyPart.Leg`。当前示例 CBM 没有额外身体限制，后续内容可以直接配置上述条件。旧 XML 的 `hotCells` 与 `grantedCellsHot` 仍作为兼容输入，转换为 `HotSwap` tag；新生成的 XML 使用 tag 列表。槽位由 Def 重建，模块存档的板 ID 与位置格式不变。

扩容器本体必须占用宿主主板的原始区域，不能放进扩展行列或子板。每块主板默认最多一个增行器、一个增列器和一个独立扩展板生成器。独立板默认 4×4，不能再次装扩容器。因此投入再多资源也不能递归制造无限空间。

新增行加在底部，新增列加在右侧，旧坐标不变。增行器仅延伸原始宽度，增列器仅延伸原始高度，同时存在时不补右下交角。各自格子只依赖对应提供者。

特别注意净收益：躯干宽 3，1×2 增行器提供 3 格，净增 1 格；手臂宽 2 时净增 0 格但改变形状。示例增行器占 1×2、增列器占 2×2；保留配置成 2×2 增行器的能力，不把所有扩容器做成相同大小。4×4 独立板净收益很高，用主板原始区域占用、唯一类别、宿主和科技等级限制它。

扩容器被任何部署模块依赖时，禁止取回列表或拆卸。提示依赖清单，玩家先处理子模块。板内重排扩容器可保留其提供板的 ID，不重建为一个新板。格子坐标和板 ID 稳定，存档不会依赖渲染顺序。

## 异常与恢复

义肢升级增加初始面积，不自动挪动 CBM。缩容后只要已部署 CBM 仍覆盖至少一个存在的格子，就保留实例、位置、朝向；其悬空部分仍绘制并占位，不自动移回待安装。完全没有支撑（包含整块板消失、缺肢）时按来源抽取回收／烧毁／遗失结果；回收成功才生成保留状态的实物。失去完整原始格支撑的扩容器停止提供空间，其子模块按同一规则处理。

容量协调在游戏更新的安全时机每秒检查一次，包含暂停状态和读档后的首次更新。地图上尝试放在角色附近；世界旅行中转入角色随身容器。对于已抽中回收的实例，放置失败保留已结算结果等待重试，放置成功后才移除；抽中遗失的实例直接移除。槽位移除和摧毁使用不同概率结算受损；完全无支撑时还可能回收、烧毁或遗失，详见 Customization.md。

保留的部分悬空模块不妨碍其他合法安装；但它自己若重新摆放，必须完整落在有效格内。未研究时仍不解锁移动；悬空不满足全格热插拔。手术仍可以取出。容量恢复后原位置自然重新获得支撑。主动拆卸仍沿用扩容依赖保护，不借缩容规则绕过拆卸流程。

布局事务先克隆候选状态，再重建板与验证全部实例，成功后一次提交。不能先删除源位置再检查目标，也不能只检查总空格数。存档读入做校验；不偷偷修复成玩家未授权的新布局。已有的部分悬空布局是允许保留的状态；新候选实例始终进行完整边界、标签、占位校验。

## 原生右侧管理面板

视觉沿用原版深色面板、字号和菜单按钮。健康页左侧保持 630×430 的原生卡片；右侧附加约 410 像素宽管理区。不能单纯把健康页 size 加宽，因为 DrawPawnHealthCard 会按总宽度重分配原版两列。

布局更新（2026-09-11）：左侧约七成区域为所选板，右侧窄栏为待安装模块。左区顶部保留部位/板选择，底部用贯穿两列的 64 像素信息栏显示所选 CBM，后续容纳配置；格子使用 32–52 像素的统一尺寸，依据横向空间决定，不随每块板高度反复缩放。删除常驻研究提醒、图例和操作说明，规则与 tag 改为悬停提示。每次选择不同角色清空拖动状态，禁止把上一名角色的拖动提交到下一名。

固定连接格使用普通背景，热插拔格使用绿色，现有格子默认不显示角标，悬停显示全部 tag。扩容器保留蓝色，扩展格浅蓝，HotSwap 格优先浅绿。格子和 CBM 均有可配置颜色的角标，CBM 底部显示耐久条。所有格使用按物理像素对齐的步长、起点和每侧 1 个物理像素留白；模块块也使用相同留白与内描边，不再混用原版描边取整。模块显示图标与简短名称，长名称截断并保留完整悬停提示。拖动时用白色边线围出所有完整合法摆放所覆盖格子的并集，包含 tag、部位、研究与扩容几何限制，实际占位和预留冲突另行计算；不是简单的矩形外框。候选仍独立进行完整验证，不能凭鼠标或部分格子位于线内就提交。拖入预览显示实际占位；鼠标放开提交，Esc/右键取消，R 旋转。选择与拖动独立：锁定模块可以选中，但不会启动拖动或显示候选；所有松手、取消、切换面板与权限失效都会结束拖动。无效落点保留原布局并清除候选，不再用仅选中状态驱动预览。

小屏幕按有效 UI 宽度处理。右侧放不下时在健康面板内切换“健康 / CBM”内容；不把半个格子板画到屏幕外，也不缩小格子到难以点击。取消主板/扩展板切换；同一部位的主板和全部独立扩展板纵向排列，间隔 24 像素，共用稳定格子尺寸和滚动区，支持滚轮及滚动条。没有模块时仍展示部位容量，便于规划。

## 内核与集成

- GridRules：不依赖游戏 DLL，负责二维几何、权限、热插拔来源、扩容依赖和原子事务。
- GridRoot：身体板的稳定 ID、原始矩形、每格连接类型。
- ModuleSpec：大小、旋转、热插拔支持与扩容方式。
- ModuleState：实例 ID、宿主区域、位置、板 ID、经手术待装/已部署状态。
- Hediff_CBMModule：将实际植入物/待装实例绑定到身体部位，保存位置与状态。
- CBMBodyProfileDef：提供原生和已验证仿生部件的基础板；未知模组通过显式配置适配。
- 专用 Recipe：手术准备与实例拆卸；拆卸 Bill 保存目标实例引用，避免同类模块删错。
- 原生健康页附加区域：绘制原版卡片和 CBM 管理区，避免更改所有健康卡绘制调用。

最小验收覆盖：首次准备安装；未研究移动拒绝；研究后同板移动；研究和热插拔均不能回待装；全热/部分热格；体外物品不能热插普通格；扩容后坐标稳定；阻止递归扩容与拆依赖；转板不被研究解锁；重叠和边界；失败事务不改状态；保存加载；原生与仿生部位。


### 面板开关与右键（2026-09-11）

默认不展开管理面板。每个 Pawn 的开关状态由 CBMPanelState 保存到存档；健康详情区左上方的 CBM 按钮切换。折叠时仅过滤 HealthCardUtility 的显示枚举，不移除实例、不更改效果、不隐藏原版义肢。宽屏显示右侧附加面板，小屏保留顶部开关并在健康卡区域切换内容。

模块右键菜单提供热拔出和手术取出；不可用原因放在禁用选项的悬停提示中，菜单本身保持短标签。待安装件也可右键安排手术取回。原版健康列表若把同类 CBM 合成一行，则先选具体实例再进入操作菜单。空槽右键不再列出物品或安装报错。

随身可热插拔 CBM 在右侧列表下方显示，右键选择热插入进入选址，左击合法位置提交，R 旋转，右键/Esc 取消。热插入仍要求所有目标格支持、实际持有物品、操作者可执行和无互斥冲突；不会经过待安装列表。

互斥配置详见 Customization.md：Part / Pawn scope，支持指定其他 CBM、自身或 CBM tag；双向判定，待安装件和有效安装队列也预占关系。


### 拖动性能

合法区域、候选结果按布局快照、拖动实例、朝向和板 ID 缓存。滚动、鼠标移动与重绘复用结果；实际提交仍从游戏状态重新验证。面板快照避免每次 GUI 事件重新扫描 Def 并生成整套规则；颜色解析与文字适配也缓存。拖动期间不注册格子与模块的悬停提示，并消费拖动事件以免传给地图交互。

取消“GUI 漏过一帧即结束拖动”的规则：帧间隔只在新鼠标按下时用于清理旧交互，正常跨帧拖动不受影响。释放、切换角色/部位和面板开关仍清除拖动。通过常规布局变化自动失效；开发者运行时修改 Def 需显式 Invalidate。


### 健康列表导航与简化

待安装件只出现在管理面板的待安装列表，原版健康列表无论开关状态都不显示它们。CBM Hediff 不带 prepared/deployed 括号后缀，状态仍保存在实例上。左击已部署 CBM 的原版条目时，管理面板选择对应部位、选中该实例并滚动至其所在板；同一合并行的实例具有相同部位，定位该行代表实例。右键行为保持原来的操作菜单。顶部部位按钮宽 132 像素，靠左放置。

颜色参数可用 None 表示无；现有格子不显示角标，CBM 状态角标保留。扩展格/模块使用 #6060AC，热插拔格使用 #73997C，在原版健康数值配色基础上降低约 25% 亮度。


### 拖放移动意图

待安装件拖入槽位、已安装件重新排列，均先保存目标板、坐标和朝向，原状态保留至角色完成 120 tick（正常速度约两秒）的调整动作。目标以暗金边框预留；白色边界只计算槽位几何、tag 和移动权限，不排除已有 CBM 或移动预留。候选格的红绿反馈独立检查实际占用和预留冲突，提交及动作结束再次校验。

每个组件同时只能有一个意图；右键“取消移动”释放预留并移除对应任务。多个组件按任务队列顺序执行，前一个动作完成前其原位置仍占用，暂不支持交换或循环依赖移动。意图和原版 Job 均随存档保存。执行中断则取消该意图；被清除且未启动的任务最迟下一秒游戏时间释放预留。容量变化使目标非法时取消意图，不改动组件原位置。安排移动要求角色在地图中、清醒、未倒地、非精神状态且具备操作能力。

本次动作化针对拖放部署／移动；随身实物的右键热插入、热拔出仍沿用已有即时操作。研究、手术和热插拔权限保持独立，待安装列表仍只由手术加入。


### 状态与来源结算（2026-09-11）

槽位消失具有 Removed / Destroyed 原因。两类都可能使部分支撑者受损，部分支撑者继续占据原位置；完全无支撑后按各自概率决定回收、受损、烧毁或遗失。一次事件只结算一次；物品放置失败保存已抽取结果，重试或读档不重抽。

受 CDDA 的污染、未灭菌与回收故障区分启发，本模组使用可叠加的 Dirty、Unsterile、BurntOut 与耐久损坏。CDDA 参考： https://github.com/CleverRaven/Cataclysm-DDA/blob/master/src/bionics.cpp 。此处损失概率和损坏强度是 RimCBM 的初版设计，不是 CDDA 数值移植。

手术回收和失去槽位后的回收产生污染／未灭菌标记；热拔出保留既有状态。烧毁件停止工作且不能拖动，其物理占位仍保留，扩容件不再提供新增格。状态在底栏、悬停与物品名称显示，详细配置和开发接口见 Customization.md。已加入清洁、维修、灭菌配方；普通维修不能恢复烧毁件。
