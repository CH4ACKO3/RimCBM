# Cataclysm: DDA CBM → RimWorld：调研与整体方案

日期：2026-09-10。状态：设计提案，尚未实现或进行游戏内验证。

后续修订：容量和植入流程以 [二维植入体系统](../ImplantGrid.md) 为准。项目现已开始槽位原型实现；本文其余内容仍是总体提案。

## 1. 推荐方向与版本基线

做一个以“植入式供能网络 + 可主动控制的身体模块 + 自动使用策略”为核心的独立模组。让玩家为工程师、突击手、野外队员配置不同的身体，而不是只沿着更高的义肢效率升级。

建议以 RimWorld 1.6 为首发目标，以 CDDA 0.I 为固定参考。官方 latest 当前指向 0.I；本地游戏反编译源码的程序集标识为 1.6.9438.37837。此程序集号不是游戏界面显示的完整版本号，实际编译与验证仍需绑定安装目录中的 DLL。[CDDA 0.I 发布页](https://github.com/CleverRaven/Cataclysm-DDA/releases/tag/0.I)；[本地程序集信息](../../../../Source/Properties/AssemblyInfo.cs)。

核心包以本体和 Harmony 为目标依赖；DLC、CE、其他义肢模组通过可选兼容包接入。独立设计 Def 与 C# 实现，不在运行时解析 CDDA JSON。每个移植模块保留来源 ID 和改编说明，方便追踪来源和更新。

## 2. 调研结论：需要保留什么

CDDA 把 CBM 物品与已安装生化装置分开定义。物品包含安装相关信息，装置定义描述身体占用、容量、费用、开关、前置与升级等。能源费用区分启动、持续、触发等情形；能力效果还涉及 C++、EOC 和 enchantment，不能把 JSON 名称搬过来就当作完整移植。[物品定义](https://github.com/CleverRaven/Cataclysm-DDA/blob/0.I/data/json/items/bionics.json)、[数据格式说明](https://docs.cataclysmdda.org/JSON/JSON_INFO.html)。

0.I 已有储能、代谢供能、外接充电、工具、感官、医疗、武器和防御等装置。这里借用能力方向，RimWorld 的具体效果和数值全部重新设计。[装置定义](https://github.com/CleverRaven/Cataclysm-DDA/blob/0.I/data/json/bionics.json)。

两个容易混淆的事实：0.I 的身体槽位检查受 `CBM_SLOTS_ENABLED` 控制，并非所有玩法都强制启用；回收装置也不只是“拆下来再装”，安装检查包含污染、未灭菌、回收后尚未复位等状态。因此，下面的默认槽位限制与合并整备流程属于本移植版的设计选择。[0.I 安装与拆卸实现](https://github.com/CleverRaven/Cataclysm-DDA/blob/0.I/src/bionics.cpp)。

现有 RimWorld 模组 Bionic modularity 已提供义肢上的模块安装、类别槽位及手术。它证明这一需求已有实现，也意味着本项目应突出共享能源与自动策略。建议把它列为兼容对象，不作为首版硬依赖；其作者页面列出了 VEF 依赖。[作者发布页](https://steamcommunity.com/sharedfiles/filedetails/?id=3589154549)。这次检索没有建立全部同类模组清单，也不能据此断言没有其他完整 CBM 移植。

| 原作要素 | 本移植版建议 |
|---|---|
| 储能、供能、能力分离 | 必须保留；装了模块不意味着可以无代价使用 |
| 被动、切换、单次、反应式能力 | 必须保留；采用统一执行与扣能接口 |
| 身体占用和模块冲突 | 简化为身体区域容量与明确互斥；默认启用，可配置 |
| 回收、整备、手术 | 保留经营循环，减少零碎工序 |
| 单人逐个手动操作 | 改为殖民者策略、批量配置和少量战斗按钮 |
| 原作秒数、焦耳和属性数值 | 重新平衡，不按现实单位直接换算 |
| 饮水、辐射等生存系统相关能力 | 本体缺乏对应玩法的模块延期；由兼容包提供 |

## 3. 玩家循环与成长路线

探索或交易获得模块 → 整备回收件 → 检查安装条件 → 手术安装 → 设置供能与自动策略 → 工作、作战、远征 → 回充、升级或换装。

早期通过商人获得基础充电接口、储能和少量生活模块。工业中期可制造基础产品；高级模块依赖先进零部件、研究与稀缺控制核心。后期通过任务和遗迹获得高性能模块，保留选择不同配装的价值。

首版使用现有交易、研究、任务奖励和工作台体系。完整 Autodoc、自建势力与大型遗迹任务留到内容扩展，避免医疗建筑流程拖住核心验证。后续 Autodoc 可作为降低人力需求的高成本手术设施，仍需供电、药物和术后护理。

回收件只有“待整备”和“可安装”两种玩家可见状态。整备配方合并清洁、复位与灭菌，消耗劳动和材料。首版不做无差别尸体拆解；正常拆卸返回待整备件，后续尸体回收只从实际存在且可回收的模块产生物品。通过回收损耗、低转售价格与整备成本避免俘虏循环变成无限利润来源。

## 4. 能源设计

### 4.1 一名角色，一个能源池

使用抽象单位 E；内部以固定精度数值保存，避免不断累积浮点误差。储能模块提供容量，供能模块把外部资源转换为 E，功能模块共享消耗。耗尽会关闭需要电力的功能，不会让原版仿生腿突然失效；未来若增加真正依赖供电的替代器官，需要另行设计生命维持规则。

首版供能仅两条路线：基地充电与代谢发电。基地充电需要接口、充电位置及实际供电；代谢发电消耗额外营养，并在营养低于阈值时停止。满电停止消耗。后续化学燃料模块可解决远征高负载，但应带来燃料物流与体积代价。

不直接给 Pawn 加 `CompPowerBattery`。原版电池使用 Wd，并参与建筑电网；人体能源使用独立模型，通过充电设施明确转换。设施只能把实际获得的电量或缓冲电量转换为 E，不能仅检查一次 `PowerOn` 就永久发电。[本地电池实现](../../../../Source/RimWorld/CompPowerBattery.cs)。

### 4.2 起始平衡参数，需实测调整

| 项目 | 提案初值 |
|---|---:|
| 基础储能模块 | +100 E，占躯干容量 2 |
| 高密度储能模块 | +250 E，占躯干容量 4 |
| 标准充电 | 100 E / 游戏小时；单席位充电设施负载初设 400 W |
| 代谢供能 | 20 E / 游戏小时，每小时额外消耗 0.05 营养 |
| 夜视 / 工具 / 温控维持 | 分别 2 / 6 / 8 E / 游戏小时 |
| 液压爆发 | 启动 20 E，持续 5 游戏秒，每游戏秒 2 E |
| 紧急保留电量 | 默认容量的 20% |

所有表内数字都是原创原型参数，不是 CDDA 数值，也不是已验证平衡。游戏时间统一按实际 tick 常数结算，UI 明确“游戏小时”与“游戏秒”。不能把现实秒、游戏小时和玩家运行速度混用。

例如 100 E 满电、保留 20 E、同时开夜视与温控，净消耗 10 E/小时，可运行 8 游戏小时；液压一次完整爆发耗 30 E，最多连续承担两次而不触及保留线。这样的配装预算可以先计算，再通过袭击与工作日实测修正。

### 4.3 调度与掉电

优先级从高到低：紧急能力、征召战斗、当前工作、生活便利。自动开启需满足成本与保留线；手动使用可突破保留线，但要明确显示剩余电量。玩家手动关闭优先于自动规则。

每次施放重新校验实际电量，不能只检查按钮是否可用。预热中的动作使用预留额度；提交时原子扣能，取消时释放。范围能力一轮施放只扣一次，不能按命中人数重复扣启动费用。持续效果按已经支付的时间区间生效，不能因低频结算获得免费作用时间。

短缺时按优先级停止模块。重新开启需要越过更高阈值并经过最短间隔，防止发电和消耗接近时反复开关。EMP 初版设计为短时模块离线，原生肢体照常工作；不增加随机永久炸毁，也不默认把所有拥有 CBM 的人都按机械体眩晕。

## 5. 身体、安装与拆卸

安装分两层：真实身体部位决定模块附着和损失；区域预算决定配装容量。默认预算提案为头部 8、躯干 16、双臂各 8、双腿各 8。眼睛、手掌等真实部位仍保留，但额度归入相应区域，降低界面复杂度。

每个模块定义可安装部位、宿主要求、区域费用、互斥标签、前置和升级链。普通模块默认同部位同类不能重复；储能允许重复但受容量约束。分布式模块可占多个区域，保留唯一主实例与实际部位绑定，不能创建多个会各自扣电的完整副本。

普通原生部位与兼容义肢都可成为宿主；未知义肢默认按明确的白名单或 Def 扩展判定，并显示原因。原版 `Recipe_InstallImplant` 会排除自身或祖先已经装上替换部件的部位，需要专用 `Recipe_InstallCBM`，不能直接照抄原生植入配方。[本地安装实现](../../../../Source/RimWorld/Recipe_InstallImplant.cs)。

首版单个模块尽量只依赖一个真实宿主部位。肢体被毁时清理其模块、技能、效果与容量；分布式模块以后采用“关键宿主缺失则离线”的明确规则。正常义肢替换手术如果会覆盖 CBM，要求先移除相关模块，并在手术清单说明。外部模组强行替换的情况由健康状态重建处理，不能凭空生成回收物。

安装条件在列出手术、开始和完成时都校验。已有排队手术不能绕过容量限制。最终校验失败时不得提交安装，也不得通过临时移除其他植入物腾出空间。拆卸必须定位到具体部位和模块实例；本地原版移除方法按 Def 查找首个实例，直接沿用会对左右同类模块产生歧义。[本地移除实现](../../../../Source/RimWorld/Recipe_RemoveImplant.cs)。

手术难度沿用 RimWorld 医疗环境与医术体系，使用当前版本的手术结果机制，不在原版失败之外再叠加一次隐藏失败抽签。失败可造成可治疗的术后损伤或模块损失；日常运行不加入随机永久报废。困难模式以后可单独启用故障件。

## 6. 内容规划

首个公开可玩版本建议 10 种模块，其中储能两级各计一种。以下全部是 RimWorld 改编效果，不表示原作效果逐项相同。

| 模块 | 改编效果 | 取舍与实现边界 |
|---|---|---|
| 基础储能 | 增加共享容量 | 身体预算、价值、手术成本 |
| 高密度储能 | 提升单位安装空间储能 | 更高科技和稀缺材料 |
| 外接充电接口 | 在充电位置补能 | 依赖基地设施和充电时间 |
| 代谢交换器 | 营养转换为电能 | 饥饿保护，额外食物需求 |
| 植入夜视 | 减轻适用工作/移动属性的黑暗惩罚 | 不凭空增加原版没有的黑暗射击惩罚，也不照亮全地图 |
| 集成工具组 | 实际建造、维修等限定工作期间提升效率 | 不免原料、不免工作台、不解锁全部制作配方 |
| 体内温控 | 激活时扩展舒适温度范围 | 不等于免疫火焰或已经积累的热射病 |
| 感觉抑制器 | 暂时降低疼痛 | 限制最低痛觉并附小幅反应代价，避免完全取代原版止痛植入物 |
| 肾上腺刺激器 | 短时移动/战斗应急增益 | 冷却与事后疲劳；不能绕过断腿等能力限制 |
| 液压肌肉 | 短时近战或体力工作强化 | 高能耗，不给予永久全局操作能力乘区 |

第二阶段加入单分子腕刃、电击、血液过滤、局部皮下防护与手电。第三阶段加入主动防御、内置枪械、化学燃料与特殊感官。

腕刃应有明确展开/收起状态，优先作为可控近战动作；不要直接删除或掉落主武器。血液过滤只处理白名单中的药物或中毒状态，并可能缩短有益药效；不调用“移除所有有害 Hediff”，不治愈所有感染，不擅自清除戒断和特殊疾病。手电会涉及移动光源更新；主动防御涉及伤害顺序；枪械涉及弹药、投射物与自动选武器，因此安排在框架稳定之后。

三种目标配装：工程师使用工具与基地充电；突击手携带较大储能和爆发模块；远征者选择代谢供能、温控与夜视。每种配装都应有明确优势，同时在电量、食物、安装空间或科技投入上作出取舍。

## 7. 自动化与交互

角色显示一条电量条和一个 CBM 管理入口；只将玩家收藏的战斗能力放入 Gizmo 栏。管理窗口显示电量、净消耗、当前条件下预计续航、身体预算，以及每个模块的状态与停用原因。充电或环境会变化时，把续航标成估计值。

提供日常、工作、战斗、远征、手动五类策略模板，支持复制到多名角色。模块级选项是关闭、自动、手动启用，并有必要的触发条件。夜视只在黑暗且相关活动需要时启用；工具只在适用工作中启用；代谢在饥饿保护线前停止。危险范围攻击首版只能手动释放。

自动充电在休息或空闲时安排，不能抢占征召、紧急救援和逃生；无法到达或断电时做退避，避免不断寻路。低电量按跨阈值通知一次。倒地者由护理者连接合适设施是后续功能，首版不能承诺自动搬运到充电床。

敌对 NPC 后续使用同一能源规则，按威胁预算生成完整可运行配装。先开放少量无友伤能力，再引入复杂目标选择。不要只给 NPC 无限电来掩盖自动使用逻辑缺失。

## 8. 技术架构

```text
ThingDef_CBM + RecipeDef             物品、安装、移除、整备
             ↓
Hediff_CBMModule                     模块存在、宿主部位、实例状态
             ↓
Hediff_CBMNetwork                    每个角色唯一：电量、预留、策略
             ↓
EnergyService / BodySlotResolver     扣能、宿主与容量校验
             ↓
EffectWorker / Ability / StatPart    被动、持续、施放、受击反应
             ↕
充电 Job / 电网设施 / 远行结算 / 管理窗口
```

`Hediff_CBMNetwork` 是内部管理状态，继承适合无部位状态的 `HediffWithComps`，隐藏在普通健康列表中；真实模块使用带实际部位的植入 Hediff。不要把管理网络做成要求 Part 的 `Hediff_Implant`，因为本地实现会对无部位植入物报错并在加载时移除。[本地植入物类](../../../../Source/Verse/Hediff_Implant.cs)。

XML 通过 `DefModExtension_CBM` 定义类别、宿主、容量成本、互斥、能耗、自动策略和效果 Worker；C# 提供可复用执行器。最初只支持单宿主、切换和单次三条简单路径，框架验证后再扩展分布式和受击反应。缓存与派生值从模块实例重建，不能将 UI 列表当权威状态。

可复用的本地接口证据：

| 接口 | 用途与注意点 |
|---|---|
| `HediffComp_GiveAbility` | 已支持植入物赋予/移除 Ability；自建来源计数，避免拆掉左侧模块时误删右侧仍提供的能力 |
| `Pawn_AbilityTracker` | `GainAbility` 按 Def 去重；多个模块不等于多个独立 Ability 实例 |
| `HediffComp_VerbGiver` | 提供内置近战 Tool/Verb 的基础；自动使用行为必须另测 |
| `CompAbilityEffect` | 提供校验、AI 目标判断与效果执行接口；统一施放事务管理扣能 |
| `StatPart_Glow` | 确定夜视实际应该改变的属性路径；不要全局伪造地图亮度 |
| `Recipe_Surgery` | 当前手术通过 `surgeryOutcomeEffect` 取得结果；保持同一套成败语义 |

源码位置：[赋予技能](../../../../Source/Verse/HediffComp_GiveAbility.cs)、[技能追踪](../../../../Source/RimWorld/Pawn_AbilityTracker.cs)、[Verb 提供器](../../../../Source/Verse/HediffComp_VerbGiver.cs)、[技能效果](../../../../Source/RimWorld/CompAbilityEffect.cs)、[光照属性](../../../../Source/RimWorld/StatPart_Glow.cs)、[手术](../../../../Source/RimWorld/Recipe_Surgery.cs)。这些是源码可行性判断，不是模组兼容验证结果。

需要 Harmony 时只接入必要节点：模块生命周期/部位替换后的重建、特定属性路径、未来的伤害反应。不要全局改写所有植入物、所有伤害或所有 Pawn Tick。普通被动属性优先使用原生 Hediff stage；状态变化时更新并正确失效缓存。

### 性能、存档与世界状态

地图上仅注册有 CBM 的角色。持续管理使用错峰低频结算，例如 60–250 tick 的候选区间；攻击、施放和紧急反应按事件处理。不能每个模块每 tick 扫描整份健康列表，也不能每个充电需求每 tick 搜索全地图。

保存 schemaVersion、电量、模块实例状态、策略、离线时限、最后结算 tick。读档后先重建模块与容量，再钳制电量、校验能力来源，最后恢复自动策略。临时施放预留若无法恢复对应 Job，应释放，不能永久占用。

地图与远行队能源结算必须互斥，按实际经过 tick 结算且分段检查营养/容量阈值，不能粗略补算导致吃成负数。装载运输容器、冷冻休眠、死亡和被世界 Pawn 休眠管理时，默认暂停主动能力与供能；恢复时不补算休眠期间能量。远行队仅允许无地图依赖的功能，效果需真实接入远行机制才计费。

## 9. 兼容策略

| 对象 | 计划 |
|---|---|
| 原版本体 | 首要验收环境；无 DLC 下启动、存档、充电和施放 |
| Royalty | 核心不引用灵能费用；与原版植入物叠加单独检查 |
| Ideology | 对身体改造态度沿用或明确接入原生判断，不伪装成普通疾病规避 |
| Biotech | 营养、黑暗适应、疼痛基因检测叠加；不把基因视为 CDDA 突变后直接删除 |
| Anomaly / Odyssey | 可选验证；突变、容器、跨地图和特殊旅行状态单列用例 |
| EPOE / RBSE 等义肢扩展 | 通过宿主适配表加入已验证替换部件，保留原义肢功能 |
| Bionic modularity | 后续选择统一预算适配或明确双预算显示，不能假装双方天然兼容 |
| Combat Extended | 独立兼容层，分别处理近战穿透、投射物、护甲和主动防御顺序 |
| 异种族、多肢体 | 按真实 BodyPartRecord 与适配配置映射，未知结构给出不可安装原因 |
| Multiplayer | 首版不宣称支持；后续同步命令、随机数与施放事务 |

本地 CE 对 `CompAbilityEffect_LaunchProjectile.LaunchProjectile` 已有专门补丁，说明部分技能投射物可沿现有路径接入，但不能据此保证所有 CBM 武器兼容。[本地 CE 接口](../../../../ce/Source/CombatExtended/Harmony/Harmony_CompAbilityEffect_LaunchProjectile.cs)。主动防御需要明确是在护甲前还是后削减伤害、如何按削减量扣电、如何避免重复回调，以及与护盾腰带的顺序；完成这些实验后才进入公开版。

目标支持中途加入已有存档：首次真实安装时创建网络，不批量改造全部旧角色。卸载模组不承诺直接安全；如需支持，应另做显式移除模块和状态的迁移工具，经过往返存档验证。

## 10. 分阶段交付与验收

| 阶段 | 交付物 | 完成门槛 |
|---|---|---|
| P0 技术纵切 | 基础储能、充电接口、液压能力、安装/移除、电量显示 | 完成获得→安装→充电→使用→耗尽→读档→拆卸闭环；义肢宿主路径可用 |
| P1 可玩核心 | 10 种首发模块、代谢发电、自动策略、交易研究、整备 | 连续殖民地游玩无需反复手动开关；三个配装方向各有用途 |
| P2 战斗与身体扩展 | 腕刃、电击、过滤、皮下防护、敌对配装、CE 验证 | 无技能残留、无能量复制、主武器不丢失、伤害结算一致 |
| P3 内容扩展 | Autodoc、遗迹任务、更多供能和高级 CBM | 新内容复用核心接口，兼容矩阵达到声明范围 |

单名熟悉 RimWorld C# 的开发者，可先按 P0 约 1–2 人周、P1 追加 3–5 人周、P2 追加 3–6 人周编排；P3 待范围确定后估算。仅用于排期讨论，不是承诺；复杂医疗流程、原创建筑美术、多模组测试和 CE 调试会显著影响工期。

优先测试能破坏存档或平衡的不变量：

1. 能源始终在 0 与容量之间；同一次施放只扣一次，取消释放预留。
2. 断电不充能、满电不继续吞营养、饥饿时停止代谢；充电席位不会重复占用。
3. 同类双侧模块正确拆卸；缺肢、换肢、死亡、复活后不保留幽灵能力。
4. 安装队列不能绕过容量；失败或中断不会复制物品与模块。
5. 保存加载、地图往返、远行与容器状态转换不重复发电、不重复结算。
6. 自动策略尊重手动关闭，不抢救援任务，不反复闪烁或刷警告。
7. 工作模块只增益目标工作；无关活动不扣费，属性缓存不会残留。
8. CE 和非 CE 分别验证武器、护甲与 EMP；未测试组合不标“兼容”。

平衡验收记录每人每日充电时间、额外食物、一次袭击技能次数、断电比例和各配装产出。用相同存档对比原版义肢配装与 CBM 配装。性能在固定场景比较未安装模组、安装但无 CBM、少量和大量 CBM 角色的 tick 耗时；首轮测量后再制定开销预算。

## 11. 开发入口

第一项工作应是 P0 的技术纵切：在既有 1.6 环境中验证“义肢上安装模块、唯一能源池、一次主动施放、拆卸读档”四件事。它们通过以后再录入内容表。这样后续每个新 CBM 都是新增配置与少量效果逻辑，避免做出几十个静态属性植入物后才重构能源和身体系统。
