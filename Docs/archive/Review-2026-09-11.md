## 需要修复的问题

### R1 · P2 · 旧运动强化器绕过统一动作与运行规则

位置：Source/RimCBM/ControlMenu.cs:69、GridPanel.cs:182、Energy.cs:136–151。

现有 RimCBM_Overdrive 仍定义 useDurationTicks，菜单直接调用 CBMEnergy.Use。地图内立即扣能并生效，没有准备动作；商队因为 CanHotSwap 要求 Spawned 而不可使用，精神崩溃检查也与新能力路径不同。这不是不可达的历史代码。

建议：迁移现有旧主动能力至 CBMAbilitySpec，旧 API 转发统一流程；保留旧存档状态迁移。补菜单实际下达动作、准备中断和商队自身使用的回归。

### R2 · P2 · 热拔插清除旧主动能力冷却

位置：Source/RimCBM/Conditions.cs:76、92；Energy.cs:137。

MakeItem / ApplyItem 搬运新 abilityStates，却未搬运旧 cooldownUntilTick，实体组件也没有该字段。可热插拔的运动强化器使用后拔出再插入，新 Hediff 冷却为零。

建议：与 R1 一起迁移；过渡期需在物品存档、复制、堆叠比较及重新植入时保留旧冷却。测试应覆盖使用 → 热拔插 → 冷却保持，以及旧存档加载。

### R3 · P2 · 能力详情耗能忽略模式倍率

位置：Source/RimCBM/AbilityDialog.cs:30。

详情使用 CBMTagEffects.Consumption，实际结算及主菜单使用 CBMModes.Consumption。第三方模式将 consumptionMultiplier 设为 2 时，详情仍显示原消耗，实际需要及消耗两倍能源。

建议：使用统一倍率计算，核对详情、菜单、供电和释放显示。增加非 1 倍模式的数值一致性检查。

### R4 · P2 · 共用物品 Def 会静默映射到错误植入体

位置：Source/RimCBM/SurgeryOutcomes.cs:64；GridPanel.cs:245–247。

两个植入方案引用同一个 ThingDef 时，失败残留及热插拔通过 FirstOrDefault 反查 HediffDef，可能得到另一个方案。当前 Def 校验不禁止这种配置。

建议：失败处理明确传入本次 recipe.addsHediff；若物品暂只支持单一身份，则验证 ThingDef 与植入体的一对一映射，在加载时报告冲突，避免依赖 Def 顺序。若支持多方案，则物品需保存具体植入体身份，相关介绍/重量/安装入口一并使用该身份。

### R5 · P2 · 自定义效果被内建 kind 限制

位置：Source/RimCBM/AbilityEffects.cs:14、25；AbilityActions.cs:18。

自定义 Worker 默认 kind 仍为 Damage，配置检查要求 damageDef，地图外判定也按 Damage 禁用。即使 Worker 明确声明不依赖地图，仍须伪装为 Heal 等内建类型才能工作。

建议：提供 Custom 类型或让 Worker 声明验证和场景要求；内建类型约束留在对应 Worker，避免扩展作者使用无关字段绕过规则。

### R6 · P3 · 无变化容量轮询反复清除面板缓存

位置：Source/RimCBM/Capacity.cs:29、114。

每真实秒检查所有相关 pawn，暂停时仍运行；Reconcile 无论有无变化都会清数值缓存、再次构造规则并使全局 PanelSnapshot 失效。其他 pawn 的无变化轮询也会使当前面板下一帧重建。

建议：保留兜底检查，但仅在结构或状态实际变化时失效缓存；避免结尾重复构建，尽量按 pawn 失效。现有连续 Get 测试没有跨后台轮询，需补跨轮询检查。这是已确认的冗余重建，尚未实测大型殖民地帧耗时，不能量化卡顿程度。

### R7 · P3 · 能力文档契约过时

位置：Docs/Abilities.md:78、119。

旧主文档仍写不支持投射物/自动走近、即时释放、充能待设计，与 AbilityActions.md、Supply.md 和实现冲突。

建议：统一说明并设置明确主入口；写清 CBMCasting.Queue 是玩家主动操作入口，Activate 是最终结算接口。

## 扩展接口缺口：与当前内建功能错误分开处理

1. **持续能力生命周期**：目前持续能力主要是 statOffsets 与供电租期。缺少启动、停用、断电、恢复及周期运行回调；护盾、净化等行为无法通过统一 Worker 扩展。建议提供明确生命周期及单实例运行状态，停机原因也作为上下文传入。位置：Abilities.cs:128。
2. **可注册反应触发器与事件上下文**：CBMTrigger 只有固定三种；Worker 得不到 DamageInfo 或攻击来源，无法通用实现反击攻击者。建议引入 Trigger Worker 与执行上下文，保留现有优先级、储备、冷却和递归保护。位置：Abilities.cs:14、188。
3. **派生配置验证**：能力、效果、故障的 ConfigErrors 非 virtual，派生 spec 添加字段时无法让校验参与统一调用。建议提供 virtual 验证入口并保留 base 校验，尤其与允许继承 fault spec 的文档保持一致。
4. **补给来源 Provider**：燃料和充电虽有公共查询/消耗接口，来源实现仍固定；第三方容器、电网需要打补丁。可补资源来源与充能来源契约，明确预检查、提交和中断语义。这是后续扩展能力，不表示现有化合燃料/充电站失效。
5. **原版暴力能力限制策略**：当前无法暴力的 pawn 仍可使用攻击效果，没有类似原版 casterMustBeCapableOfViolence 的开关。需要确定产品规则并做成可配置约束；不将未明确提出的限制认定为现有需求违约。位置：Abilities.cs:159；原版 work/decompiled-rw16/RimWorld/Ability.cs:760。

补充维护建议：Access.cs:65 每次宿主 tag 查询都会实例化所有 Provider Worker，可按 Def 缓存无状态 Worker，并明确其生命周期。此处同样没有实测性能数据。
